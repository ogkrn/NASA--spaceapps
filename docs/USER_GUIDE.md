# A short reviewer walkthrough

1. Start both local services and open the frontend. Read the evidence/scenario banner once: the numerical controls are a what-if exercise.
2. Choose Moon or Mars, then a site card. The globe is a procedural orientation illustration; if WebGL is unavailable, use cards. Read the selected site's source panel below the main view.
3. Open Analog Discovery. Select an Earth location, read the source evidence and identify the experiment it could support. Its index is a subjective profile ranking, not a percentage of real environmental equivalence.
4. Open MCDA Ranking. Change a priority and compare how the order changes. The displayed weight percentages are normalized. Rankings reflect assumptions and preferences, not landing approval.
5. Open Mission Simulator. Change crew, duration, power strategy, mining, water recycling or burial. Press Execute Simulation. An edited-settings notice means existing results belong to the previous run. Expand the assumptions and telemetry; inspect oxygen, water and power deficits and first failure day.
6. Open a Site Briefing for a plain-language account, or toggle Educational Mode for lessons and a quiz. The briefings are templates using the catalog, not generated research.

## If something fails

An API failure produces a visible message instead of a made-up result. Confirm the backend is running at port 8000, then use Retry/reload. Rebuild after changing production proxy settings. If the globe cannot render, the rest of the app remains accessible. Keep a local recording as a backup for presentation; do not imply the recording proves scientific validity.

## A defensible presentation sentence

“We connect source-backed descriptions of known terrestrial analogs with transparent scenario rankings and a resource-budget demonstrator. Our engineering inputs are illustrative; a next phase would extract comparable observations and validate the rankings.”
